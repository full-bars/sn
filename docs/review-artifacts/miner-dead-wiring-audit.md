# Miner dead-wiring audit

Base: `main` at `20353851` (`docs(bittensor): refresh the SN25 live numbers`). Every file:line below is at that SHA unless a different SHA is named. 3.23 reference: `full-bars/urnetwork-3.23-fix` at `9f0db99` (read only), package `provider/`.

Scope: functions, methods, exported hooks and registered handlers in package `miner` that exist (often with a passing unit test) but that nothing in the production `cli/miner` binary calls. This is the class that produced the `notifySystemdReady` outage fixed in `3ad5ad36` (merged in `65910c22`). No production code was changed by this audit.

## Classes

- **A**: ported from the 3.23 provider (or, marked **A\***, written in this fork) with a comment, test or commit message that says it is meant to run, and never called in production. These are the dangerous ones.
- **B**: deliberately unused for now; a comment or commit message says so (quoted).
- **C**: dead. Superseded by another code path, a test-only accessor living in a production file, or a helper whose caller was removed.

## Tool limits

- deadcode uses RTA: a method on a type that reaches reflection (for example `json.Marshal(s)` in `persistProxySlowRetryState`) is treated as reachable. That is why the seven `proxySlowRetryState` methods in finding #2 are not in its output; a name-reference grep over production files found them (and only them, apart from SDK/connect listener methods reached through interfaces).
- deadcode and staticcheck analysed GOOS=linux only; darwin/windows/freebsd-only files were not analysed.
- staticcheck U1000 does not report exported symbols or functions referenced by tests, so it sees only the "dead even from tests" subset.
