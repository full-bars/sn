# v2026.9.17-1789646883-meso

## Summary

This release includes the CI and release pipeline work in this repo. Every workflow now runs, release assets ship with the installers, and all installers download from the official GitHub release. A container discovery bug was also fixed so the Go tooling can find provider containers under the new image name.

## 1. Release Pipeline

The release workflow now aligns with the mature fork:

- The universal tarball bundles the Linux installer as `urnet-tools`. Installers and scripts fetch this exact name from the release.
- Per-platform tarballs for linux, darwin, and windows each carry their own installer script.
- A monitoring bundle ships with every release. It contains the Prometheus and Grafana compose stack and dashboards.
- Release notes come from `releases/<tag>.md` when present. Otherwise GitHub auto-generates them.
- VirusTotal and ClamAV scans moved to a parallel job. They append the verdict to the release body and stage submissions for Microsoft Defender. They never block publication.
- All 18 binaries ship as standalone assets named `urnet-tools-<os>-<arch>` and `urnet-docker-<os>-<arch>`. The Go tool self-update and the installers pull these exact names.

## 2. Installers Ported

Six installers are new to this repo:

- `Provider_Install_Mac.sh`
- `Provider_Install_Win32.ps1`
- `Provider_Install_Deps.sh`
- `Provider_Uninstall_Linux.sh`
- `Provider_Uninstall_Win32.ps1`
- `install-urnet-docker.sh`

All installers download release assets from the official GitHub release. No custom mirror is used. The help text contact address is unchanged.

## 3. Workflows Restored

Seven workflows were disabled stubs in this repo. They are restored and running:

- Dash/POSIX compatibility
- Windows lifecycle verification
- Unix lifecycle verification
- CFAA blocklist sync
- Tool functional smoke
- Functional soak
- Docker multi-container

The pre-release shakedown workflows are restored too. Their tag triggers now use the v2026 release scheme of this repo. Every workflow runs on the correct event: main push, pull request, scheduled sync, or version tag. Docs-only changes skip CI.

## 4. Docker Container Discovery Fix

The Go tooling identifies provider containers by image and container name. The matcher only recognized the old image name. The new image `ghcr.io/full-bars/sn` did not match, so tools could not discover provider containers after the rename.

The matcher now recognizes `full-bars/sn`. Daemonized features work inside Docker again, including hotswap, status, logs, and the proxy commands.

## 5. Docker Build Fixes

Two issues broke container builds:

- The `.dockerignore` excluded the `provider/` source directory. The pattern matched a real directory name, not the built binary. The ignore list now names the actual output files.
- The `third_party/` directory was not copied before manifest download. The npipe local package requires it. It is now copied first.

Multi-arch images build for amd64 and arm64. They push to both `ghcr.io/full-bars/sn` and `3cape/sn` (DockerHub) on version tags and main pushes.

## 6. Pelican Egg

A Pelican panel egg ships with this repo. It supports stable, nightly, and jwt startup modes. Credentials stay admin-only. `PELICAN=yes` disables runtime self-update inside the container so the image remains the single source of truth.

## 7. Documentation

Three docs are new:

- `FORK_CHANGES.md` tracks every fork modification.
- `PROJECT_STRUCTURE.md` maps the repository layout.
- `CHANGELOG.md` records release history.

Internal rollout documents were removed from the repository.

## 8. Runtime changes after the pipeline work

- **DoH server-score cache removed** (`01b8e5f5`): a live-fleet probe (ATL/ATL2/honk) showed the cache was inert — the v2026 connect lookup path never calls into it, so it wrote no `.doh_scores` and logged zero to one lines. The ported cache and its provider call sites are deleted; the DoH resolver itself (`net_http_doh.go`) remains active.
- **JWT build mode autodetect** (`77e215ca`): the Docker entrypoint selects jwt mode automatically when an auth code is passed positionally or via `URNETWORK_AUTH_CODE`; an explicit `BUILD=` still overrides.
- **Installer regression suite ported** (PR `#6`): six installer/update test scripts (~1,760 lines) ported from the mature fork and rebranded for sn's tag scheme — covering bad tarballs, wrong binary names, latest-release fallback, help text, and no-args exit codes. All six review findings were fixed before merge (isolated HOME/network mocks, digest-aware mock `jq`, exit-code propagation).
- **Wiki ported into `docs/`** (PR `#5`): the fork wiki now lives in-repo and auto-syncs to the GitHub wiki.

## Deploy Notes

- `urnet-tools update` picks up the new tool binary and provider tarball.
- Container users re-pull the image. The image updates the provider inside.
- Existing installs update in place. Hotswap applies without downtime on systems running a hotswap-capable version.
- The monitoring bundle deploys with the compose stack in `monitoring/`.
- Docker users can drop `BUILD=jwt` — when `BUILD` is unset, passing the auth code positionally (or `URNETWORK_AUTH_CODE`) selects jwt mode; an explicit `BUILD=` value still overrides.
