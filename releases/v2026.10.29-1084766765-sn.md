## Quick start

> [!TIP]
> **Already running a provider?** Update in place - no reinstall, no new auth code:
> ```bash
> urnet-tools update
> ```

### Install a provider

```bash
# Linux (also Alpine and OpenRC, from a root shell)
curl -fSsL https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_Linux.sh | sh

# macOS
curl -fSsL https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_Mac.sh | sh -s -- install
```

```powershell
# Windows (PowerShell)
irm https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_Win32.ps1 | iex
```

FreeBSD has its own installer, `scripts/Provider_Install_FreeBSD.sh`.

Then authenticate once and load your proxies:

```bash
urnetwork auth
urnet-tools proxy add ~/proxies.txt
urnet-tools proxy refresh
urnet-tools status
```

> [!WARNING]
> Windows Defender flags the unsigned binaries and the PowerShell one-liner. The workaround is on the Installation page.

### Run the Docker provider

The container name must contain `urnet`, otherwise `urnet-docker` cannot find it.

```bash
docker run -d \
  --name=urfix \
  --pull=always \
  --restart=unless-stopped \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  --sysctl net.ipv4.ip_forward=1 \
  -e AUTHCODE='YOUR_AUTH_CODE_HERE' \
  -e HOST_HOSTNAME=$(hostname) \
  -v urfix_config:/root/.urnetwork \
  -v /path/to/proxy.txt:/app/proxy.txt \
  ghcr.io/full-bars/sn:latest
```

Passing an auth code selects the auth-code path on its own; the image does not need `BUILD` set.

> [!CAUTION]
> Auth codes are single-use. The token is saved to the `urfix_config` volume on first run, so keep that volume - without it you need a new auth code.

### Run the miner

Same naming rule applies.

```bash
docker run -d \
  --name=urnet-miner \
  --pull=always \
  --restart=unless-stopped \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  --sysctl net.ipv4.ip_forward=1 \
  -e AUTH=authcode \
  -e AUTHCODE='YOUR_AUTH_CODE_HERE' \
  -v sn_miner_data:/root/.urnetwork \
  -v /path/to/proxy.txt:/app/proxy.txt \
  ghcr.io/full-bars/sn:miner
```

Mining operators is opt-in and covered separately in the Miner Image page: `OPERATOR` with a hotkey seed, or `ALL_OPERATORS=Y` to mine every listed operator. The default run above needs none of them. The miner image is the one that reads `AUTH`; the provider image selects its auth path from the auth code alone.

## What changed

> [!IMPORTANT]
> A running provider keeps its current binary in memory. Every **[redeploy]** entry below takes effect on the next restart or `urnet-tools update`.

## State store

**Persistent machine state** [redeploy] moves machine records into a transactional bbolt database. Operator settings remain in their editable file. The auth backoff is migrated without deleting its old copy. The store also persists the extender activation budget. ([#258](https://github.com/full-bars/sn/pull/258))

**Store open retries** [redeploy] are throttled after a failed open and the failure is counted. This avoids repeated lock waits and log messages. ([#263](https://github.com/full-bars/sn/pull/263))

**Store recovery and transactions** [redeploy] distinguish unreadable records from missing records, isolate corrupt stores and protect activation budget updates in one transaction. A successful activation clears the refusal wait without refunding the attempt window. ([#278](https://github.com/full-bars/sn/pull/278))

**Store failure handling** [redeploy] releases the lock after an open panic, treats empty stored values as unreadable and keeps the activation budget held after quarantine. Failed refusal writes can be retried, and decode failures no longer count as write failures. ([#311](https://github.com/full-bars/sn/pull/311))

## Extender activation and refusals

**Host-aware activation charges** [redeploy] charge a pass for the address families the host can use. The host is rechecked as its network changes. Refusal backoff stops at the hourly window and an old streak can expire. ([#262](https://github.com/full-bars/sn/pull/262))

**Per-client activation budget** [redeploy] tracks attempts and refusal waits by provider client identity and carries forward the old record. The local budget does not coordinate separate hosts that do not share their state store. ([#268](https://github.com/full-bars/sn/pull/268))

**Probe and refusal fixes** [redeploy] require a valid DNS response before calling IPv6 usable and retry a failed probe. A spare activation post can retry a failed family. Transient activation errors no longer create a refusal backoff. The fixes were carried onto main after they missed their original branch merge. ([#270](https://github.com/full-bars/sn/pull/270), [#273](https://github.com/full-bars/sn/pull/273))

**Unavailable activation records** [redeploy] no longer cache a store error as a refusal for the lifetime of a slot. Startup retries three times, one second apart, and the first launch asks again. If the record remains unreadable, one launch per process can proceed uncounted; a restart can use that allowance again. A store handed to a hot-restart candidate keeps the role off. Genuine budget and backoff refusals remain cached. ([#314](https://github.com/full-bars/sn/pull/314))

**Refusals that survive a failed write** [redeploy] journal a refusal, retry the write when it fails, and quarantine a store that cannot be read. A launch that cannot be counted is withheld rather than spent. A refusal is retried when the platform reports the same status again, so an unchanged status no longer hides a lost write. ([#315](https://github.com/full-bars/sn/pull/315))

## Proxy pool and credentials

**Slot identity recovery** [redeploy] tries saved legacy identities and can mint a replacement when none is available or an adopted identity is rejected. Explicit revocation of an identity with a durable registration record remains a refusal. The old registration flag is accepted but no longer prevents creation. ([#266](https://github.com/full-bars/sn/pull/266))

**Capture identity custody** [redeploy] prevents hot-restart reuse when a cached client does not match the identity retained by a capture profile. ([#275](https://github.com/full-bars/sn/pull/275))

**Cached identity validation** [redeploy] checks the stored client identity against the custody credential and JWT claim before reuse. A newly minted credential must be saved before the slot runs. A follow-up test checks both the returned credential and client ID. ([#282](https://github.com/full-bars/sn/pull/282), [#287](https://github.com/full-bars/sn/pull/287))

**Safe proxy reloads** [redeploy] keep the working pool when the URL cache is unreadable or a file yields no valid entries. Partial file errors are reported and malformed source lines are redacted. ([#284](https://github.com/full-bars/sn/pull/284))

**Slot ownership and state** [redeploy] remove exited workers from the correct generation, record runtime additions and their sources, and put health writes in the shared state transaction. Credential rotations must pass verification before replacing a working credential. ([#285](https://github.com/full-bars/sn/pull/285))

**Credentials survive a proxy add** [redeploy] keep `user:pass@host:port` intact when adding from a file, and reject malformed input instead of writing it and echoing the password in clear text. Both accepted forms are checked against what the file actually receives. ([#322](https://github.com/full-bars/sn/pull/322))

**Source secret redaction** [redeploy] hides credentials in malformed source lines and in source add and remove output. Status also removes userinfo, query strings and fragments from displayed source URLs. ([#307](https://github.com/full-bars/sn/pull/307), [#309](https://github.com/full-bars/sn/pull/309))

**Reload and rotation safety** [redeploy] locks reloads against clear operations, tests each candidate credential before caching it and keeps a failed candidate's grade off the working credential. Removed workers retire before replacements start, and the run remains alive for retries and replacement workers. ([#312](https://github.com/full-bars/sn/pull/312))

**Startup and platform slot coordination** [redeploy] locks the startup state transaction across processes and seeds the reload watcher so it sees a clear during startup. Replacement workers wait for the platform slot, including when the username changes. Reload waits end when the run stops. Proxy commands also hold the lock across exclusions and matching removals. An interruption can leave an exclusion with some matches still present; rerun the command to finish. Clear reports lock and read errors and triggers a reload after each attempt. File-backed credential replacement preserves existing mode and ownership; new files are private. ([#317](https://github.com/full-bars/sn/pull/317))

**Proxy identity redaction** [redeploy] hides raw identity keys and unsafe addresses in slot, restart, dial and reload output. Malformed addresses display a placeholder. ([#321](https://github.com/full-bars/sn/pull/321))

The tool reports that blocker instead of suggesting an ineffective version upgrade. The existing provider stays running. **Control surface corrections** [redeploy] validate queued overrides when applied, restore startup memory limits when their overrides are cleared and report an unreachable control socket instead of saying a key is unset. ## Proxies and network

**H3 ranking** [redeploy] excludes the direct identity from proxy ranking. Setting an H3 proxy limit no longer panics on a direct-only provider. ([#310](https://github.com/full-bars/sn/pull/310))

**Proxied provider streams** [redeploy] use the configured proxy for TCP relay traffic as well as UDP. A failed proxy dial does not fall back to a direct connection. ([#280](https://github.com/full-bars/sn/pull/280))
