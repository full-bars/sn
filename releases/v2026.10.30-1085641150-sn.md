# v2026.10.30-1085641150-sn

Released 2026-10-30

## Quick start

> [!TIP]
> **Already running a provider?** Update in place - no reinstall, no new auth code:
> ```bash
> urnet-tools update
> ```

### Install a provider

```bash
# Linux (also Alpine and OpenRC, from a root shell)
curl -fSsL https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_Linux.sh | sh

# macOS
curl -fSsL https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_Mac.sh | sh -s -- install
```

```powershell
# Windows (PowerShell)
irm https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_Win32.ps1 | iex
```

FreeBSD is a two-step install because the installer runs with `sudo` and resolves the release tag before fetching:

```sh
fetch -qo urnet-install.sh https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_FreeBSD.sh
sudo sh urnet-install.sh install
```

Then authenticate once and load your proxies:

```bash
urnetwork auth
urnet-tools proxy add ~/proxies.txt
urnet-tools proxy refresh
urnet-tools status
```

> [!WARNING]
> Windows Defender flags the unsigned binaries and the PowerShell one-liner. The workaround is on the [Installation page](https://github.com/full-bars/sn/blob/main/docs/Installation.md).

### Run the container

```bash
docker run -d \
  --name=meso-miner \
  --pull=always \
  --restart=unless-stopped \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  --sysctl net.ipv4.ip_forward=1 \
  -e URNETWORK_AUTH_CODE='YOUR_AUTH_CODE_HERE' \
  -e HOST_HOSTNAME=$(hostname) \
  -v meso_miner_data:/root/.urnetwork \
  -v /path/to/proxy.txt:/app/proxy.txt \
  ghcr.io/full-bars/sn:latest
```

One image: `:latest` carries `urnet-tools` and `urnet-docker`. `URNETWORK_AUTH_CODE` is the variable the image reads; when it is set the auth-code path is selected on its own, so `BUILD` is not needed. The `:miner` image runs the same binary with a different entrypoint and is being retired.

> [!CAUTION]
> Auth codes are single-use. The token is saved to the `meso_miner_data` volume on first run, so keep that volume - without it you need a new auth code.

## What changed

## Extender role

**The extender role gets the fix it needed to activate** [redeploy]. A provider could bind TCP 443 and serve TLS, yet its activation posts to the network failed with `http request attempts exhausted`. The cause was in `connect`, the networking library this release pins: it derived no alt host for the `api`, `api-v4` and `api-v6` names, so an activation posted to `api-v4` went to the family-agnostic alt host instead of `alt-v4`, and could arrive over the wrong address family. The new `connect` pin maps those three names to `alt`, `alt-v4` and `alt-v6`, the same way it already did for the `connect` names. (connect `579e90c55`, which answers issue 229 in `urnetwork/connect`.) If you run the extender role, update and restart, then read the log as described on the [extender page](https://github.com/full-bars/sn/blob/main/docs/Extender.md).

**A failed activation now says why** [redeploy]. The `[extender]activate v4 err =` and `[extender]activate hello err =` lines used to print only `http request attempts exhausted`. They now follow it with the cause each attempt kept (dial, TLS, QUIC, DNS or deadline), and a cause that repeated is shown once with a count. The line never includes the request URL, headers or token. The status record still holds the short message; only the log line carries the causes. (connect `04505b369`)

## Dependencies

**`connect` and `sdk` pins moved** [redeploy]. `connect` moves from `cff307c11f6e` to `d0a4bb41c300`, a sync with upstream `urnetwork/connect` `89d943bb7`. `sdk` moves from `d9e2cd4f4c15` to `f17fc47e8bda`, which merges upstream `sdk` `215caab7` and keeps the fork's own commits. The `connect` range also carries upstream changes outside the extender, among them a hold on contract requests while the platform rate limits a client, handling of the platform's request to close contracts now, a fix for overflow in bounded HTTP and WebSocket reads, and the 2026-10-27 IP security and blocker update. (`13d437b23`)

## Upstream sync

**`urfoundation/sn` merged through `860762731`** [redeploy] (merge `f085bf550`, 50 commits). Most of it is validator and protocol work that does not run in the miner. Two changes reach the miner side: `provider status` now reports a sign-in made with `--all-operators`, which it used to show as "Signed in: no" because those sign-ins live under `operators/<domain>` (`758387b53`), and owned API requests keep a failed HTTP/2 health check retryable (`b67f0b1a6`, `869f336f3`). The merge kept the fork's state store, single-operator identity read and consent recovery.

## Tools

**Container discovery matches the image repository** [redeploy]. A container counted as a provider if its image or name contained a substring, so `my-urnetwork-test` qualified. Discovery now compares the image repository (tag and digest removed) against a list of repositories this project publishes, and `--unit` resolves a name directly. To add your own repository, set `URNET_DOCKER_IMAGE_REPOS`. ([#329](https://github.com/full-bars/sn/pull/329))

**`--i-am-on-my-own-workstation` is gone** [redeploy]. Seed signing now asks a person at the terminal or refuses. Passing the old flag fails with a message that says it was removed, so an old script stops instead of being silently accepted. The browser signing form no longer asks for it at all, because that form never touches a seed. ([#331](https://github.com/full-bars/sn/pull/331))

## CI and docs

**The release scan fetches a ClamAV database** [no redeploy]. The package ships no signatures, so on a clean runner the scanner had nothing to load. The scan now fetches a database with retries and reports a database failure as such. (`64b32f65f`)

**Two tests no longer depend on the runner** [no redeploy]: the scan test supplies a fixture database for an empty scan target, and the claim-queue schema checks run isolated. (`887f24f04`, `1569d59a8`)

**New and updated pages** [no redeploy]: an [extender page](https://github.com/full-bars/sn/blob/main/docs/Extender.md) covering the port 443 requirement and its log lines, a wallet consent page with the signing screenshot, and refreshed SN25 numbers.
