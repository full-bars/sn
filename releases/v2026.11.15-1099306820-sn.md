# v2026.11.15-1099306820-sn

**Released:** 2026-11-15.

Previous release: [v2026.11.14-1098572730-sn](https://github.com/full-bars/sn/releases/tag/v2026.11.14-1098572730-sn).

This release fixes a hotswap bug that could leave a miner dead after the old process exited. It moves the `connect` pin to a commit that removes the OS thread per UDP readiness shard, turns on loopback diagnostics by default, and makes `urnet-tools` more reliable on hosts with file capabilities and instance units. A host that runs `Restart=on-failure` gets a restart safeguard during the update.

Update and restart. The hotswap fix is in the process that does the hotswap, so restart once after you update. A hotswap from an older build to this one has no test yet.

Legend: **[redeploy]** needs the new provider, tool or container image. **[installer]** needs the updated installer or script. **[no redeploy]** covers documentation, CI and tests.

## Quick start

Already running a provider? Update in place:

```sh
urnet-tools update
```

Install on Linux or Alpine:

```sh
curl -fSsL https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_Linux.sh | sh
```

Install on macOS:

```sh
curl -fSsL https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_Mac.sh | sh -s -- install
```

Install on Windows in PowerShell. Windows Defender can flag the one-line form as a false positive, because the script downloads and unpacks a program. The safer way has two steps. Download the script, read it, then run it from disk:

```powershell
irm https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_Win32.ps1 -OutFile "$env:TEMP\install-win.ps1"
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\install-win.ps1"
```

The Installation guide lists the Defender labels you may see and what to do about them.

On FreeBSD, download the installer and run it with a non-root service account selected:

```sh
fetch -qo urnet-install.sh https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_FreeBSD.sh
sudo sh urnet-install.sh install
```

OpenBSD support is experimental. The installer and the service have not run on an OpenBSD host. Durable client registration is unavailable there. Do not deploy OpenBSD providers to production yet.

On OpenBSD, the installer needs `jq` or `python3` to read the release metadata. Install `jq`, download the installer and run it with an existing non-root service account (replace `urnet` with its name):

```sh
doas pkg_add jq
ftp -o urnet-install.sh https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_OpenBSD.sh
doas env SERVICE_USER_OVERRIDE=urnet sh urnet-install.sh install
```

The installer does not sign the provider in. Sign in as the service account with a single-use auth code from https://ur.io, then restart the service. The OpenBSD guide has the exact commands.

Start a new provider container:

```sh
docker run -d --name urnetwork --restart unless-stopped \
  -e URNETWORK_AUTH_CODE=YOUR_AUTH_CODE_HERE \
  -e ALLOW_CLIENT_REGISTRATION=Y \
  -v urnetwork_config:/root/.urnetwork \
  ghcr.io/full-bars/sn:latest
```

Auth codes are single-use. Keep the state volume. If an existing identity is missing, restore its original volume instead of authorizing a replacement. For optional extender ports, see the [extender guide](https://github.com/full-bars/sn/wiki/Extender).

## What changed

### Fixed

- **A hotswap on a host with RAM logs no longer kills the new miner. [redeploy]** The new process inherited the old process's log pipe as its error output. When the old process finished draining and exited, the next write to that pipe ended the new process with SIGPIPE. systemd counts SIGPIPE as a clean exit, so a unit with `Restart=on-failure` stayed dead. The old process now passes on the original log destination. A new process that still inherits an orphaned pipe drops it at startup when RAM logs are on, and a later hotswap redirects a `/dev/null` error output back to the RAM log. The long-running `provide` command ignores SIGPIPE.
- **A systemd unit restarts the provider after SIGPIPE. [installer] [redeploy]** The installer writes `RestartForceExitStatus=SIGPIPE` and warns when a restart override defeats it. `urnet-tools update` checks the effective unit settings on existing hosts. If protection is missing, it writes one drop-in file, reloads systemd and checks the result. It does not restart the miner. It writes nothing when the operator blocks SIGPIPE with `RestartPreventExitStatus`, and it says so. `urnet-tools status` shows a warning for an unprotected unit.
- **`urnet-tools update` no longer reports "failed to update" after a good restart. [redeploy]** A provider binary with file capabilities hides `/proc/<pid>/exe`, and the updater took that for a failed restart. It now accepts the restart when the control socket reports the new version on a new or freshly started process, or when the process started after the binary swap and the installed binary carries the new version stamp.
- **`urnet-tools` sees more than `urnetwork.service`. [redeploy]** It lists and updates `urnetwork@*.service` instances. No unit is deleted or disabled.
- **A trimmed node no longer reads degraded because of the proxies the trim holds back. [redeploy]** `urnet-tools status` and `top` counted every configured proxy, including the ones the trim cap parks on purpose, so a healthy node showed `DEGRADED` and "3041 of 4408 proxies down". The counts now cover only the running pool, the held-back proxies are reported as `parked` in the snapshot, and a node with a healthy running pool stays `flowing` or `idle`.
- **A busy node no longer runs thousands of threads. [redeploy]** Each UDP readiness shard waited in a blocking `epoll_wait`, which held one OS thread per shard, and the provider runs two shards per proxy. A node with 1,000 proxies held about 2,100 threads, 2,100 epoll descriptors and 2,100 eventfds. The `connect` pin moves to a revision where the shards wait through the Go network poller and park as goroutines. The shards themselves remain, about four for each proxy once its IPv4 and IPv6 UDP paths are both in use. On one node with 900 proxies the thread count stayed at 13 for four hours after the update, with about 3,600 shards parked as goroutines.
- **OpenBSD service commands keep doas when its configuration cannot be read. [redeploy]** A missing `/etc/doas.conf` still selects sudo. Other inspection errors are left for doas to report.

### Added

- **Per-carrier extender statistics. [redeploy]** The extender counts served and refused requests for `tcp-443`, `udp-443`, `udp-4053` and `udp-53`, with the refusal reason. Active minutes write one summary line. `urnet-tools extender status` shows a `Carriers:` block, and `/metrics` exports `urnet_extender_carrier_requests_total` and `urnet_extender_carrier_refused_total`. Windows of 24 hours and 7 days are not part of this release.
- **Loopback diagnostics are on by default. [redeploy]** The pprof listener starts on `127.0.0.1:6060` so a stuck miner can be inspected without a restart. `urnet-tools set pprof off` turns it off. `urnet-tools set pprof <ip:port>` moves it. An explicit `URNETWORK_PPROF` still decides the address when set. If the default port stays in use after the hotswap retry, the miner binds a free loopback port.

### Changed

- **The startup GOGC line flags an environment value that differs from the live runtime setting. [redeploy]** It reports the live value and leaves its source unknown instead of attributing it to the environment.
- **ClamAV gates the release and the Docker images. [no redeploy]** The release and image workflows fetch fresh signature definitions with `freshclam` before each scan. A detection, a scanner failure, a stale database or a failed refresh stops the release or the image push. VirusTotal still runs after publication and never gates.
- **The ClamAV scan limits rise to 3000M per file and 8000M in total. [no redeploy]** The combined release archive is larger than the old 1000M limit, which stopped the first release attempt. A file over the new limit still fails the scan.

### CI and tests [no redeploy]

- The systemd shakedown runs a real hotswap in both RAM log modes and fails on a killed successor. It disables the test unit start limit during rapid restart checks and passes shakedown variables through sudo by name. This hotswap case has not run in CI yet.
- Version-detection tests build their own fixture and no longer depend on inherited build flags.
- Installer tests align the capability and digest fixtures with the live `getcap` and release metadata formats.


## Known limits

- The shakedown hotswap case has not run in CI.
- A hotswap from an older build is not covered by a test.
- The carrier statistics have not run on a live extender host.
- The OpenBSD runtime was not run on a real OpenBSD host, and durable client registration is unavailable there.
