# v2026.10.21-1077735390-meso — 2026-10-21

> [!IMPORTANT]
> **This release carries the Go 1.27.3 build for `CVE-2026-111943`, the one-program port, and the upstream mainline.** Go 1.27.3 blocks eight compromised eMudhra intermediate CA keys, but only in binaries built with it, so a node left on an older release may continue trusting them. The `provider` now carries the 3.23-fix operator surface, so unmodified `urnet-tools` and `urnet-docker` drive it. The upstream mainline is merged through `6608298e`.

This release also adds `provider wallet sign` and `provider wallet status`, signed hotkey wallet delegation, and OpenRC and FreeBSD support, and it removes the retired hub report commands. Operators who only want to be paid on Subnet 25 need one thing: sign the wallet consent once from their own computer, as the [Bittensor Quick Start](../docs/Bittensor-Quick-Start.md) shows. Nothing changes on the nodes.

## What's Changed

### Added

- **The provider captures goroutine and heap profiles on the way into a stall**: it samples its goroutine count and its heap against the soft limit every 10 seconds and, on a build-up (1.5 times the 30-minute low and at least 20,000 goroutines, heap at 90%, heap at 120%), writes the biggest goroutine stacks, the full goroutine profile, a heap profile and the numbers to `~/.urnetwork/incidents/`. The goroutine-growth trigger waits 45 minutes after a start, because the count climbs on its own while the proxies authenticate. At most 6 a day, newest 8 kept, disk only. `URNETWORK_INCIDENT_CAPTURE=0` turns it off.

- **A swap-thrash watchdog with a supervised restart** ([#77](https://github.com/full-bars/sn/pull/77)): memory pressure alone does not say "thrashing". The watchdog senses PSI memory `full`, swap activity, page refaults and direct reclaim, and tracks one state: `calm`, `under-pressure`, `thrashing`, `critical`. It first freezes pool growth; when the condition persists it restarts the provider by exiting with status 75, which the shipped unit (`Restart=on-failure`) turns into a supervised restart. The restart is capped at 3 per 24 hours with a growing backoff, is skipped while a hot-swap is in flight, and refuses to act when the swap belongs to another process. A restart leaves a thrash cap in `~/.urnetwork/thrash_cap.json` so the next start begins leaner — about 60% of the previous running count, at least one proxy, and no new cap when nothing was running before the restart. It rides the existing self-heal switch; with self-heal off it senses and logs but never restarts anything.
- **`urnet-tools status` prints the pressure summary sentence**: the live block's pressure row shows the provider's one-sentence summary (the `summary` the provider persists to `~/.urnetwork/pressure_status`), instead of only the score. Older providers keep the bare score.
- **The installer warns when a restart-policy override weakens the watchdog**: a drop-in with `Restart=no`, `Restart=on-success`, `Restart=on-abnormal`, `Restart=on-watchdog` or `Restart=on-abort`, a `RestartPreventExitStatus` listing 75, or a `SuccessExitStatus` marking 75 a success under `Restart=on-failure` would leave a detected thrash unrecovered; the installer now says so. The policy itself is never rewritten.
- **A container can use the thrash watchdog's exit 75 restart** ([#84](https://github.com/full-bars/sn/pull/84)): the watchdog's supervised restart used to be allowed only under systemd, so a container always declined it. A container (`/.dockerenv` or `URNETWORK_CONTAINER=1`) now counts as a supervisor like systemd, so self-heal is the one switch. Before exiting it proves the state directory holding `thrash_cap.json` can be written and read back; when it cannot, the escalation is refused as `persist-failed`, so a self-exit cannot loop without its throttle record. The write probe is bounded by the same timeout as the cap write, so a hung volume cannot stall the watchdog. The start scripts treat exit 75 as a planned restart.

- **A stalled provider is now recovered in a container too**: on systemd a unit that sets `WatchdogSec=` is restarted when the provider stops pinging, but a container's start script has no such watchdog, so a provider that was alive and making no progress (a heap far over its limit, every loop stuck) was never restarted there. The same detection now runs in a container with a different action: after 10 minutes without a tick the provider exits with status 75 itself, which the start script turns into a restart, leaving the same lean start cap and counting against the same 3 per 24 hours restart ring. Same self-heal switch and 30 minute startup grace: with self-heal off it logs what it would have done and keeps running. The exit is refused when the state directory holding `thrash_cap.json` is not writable, so a self-exit cannot loop without its throttle record.

- **The `/metrics` scrape now carries the connect library's stream, P2P transport, TLS handshake and dial backoff accounting**: the provider appends it to its own exposition. `urnet_stream_*` tracks live sequences by kind, opens, closes, lifetimes and control frames for the streams the provider carries, `urnet_p2p_*` tracks the direct WebRTC hops, `urnet_tls_handshakes_total{path,host,result}` shows which dial path and target takes full handshakes, and `urnet_dial_backoff_long_tier_*` shows identities waiting in the long backoff tier. See [Monitoring](docs/Monitoring.md) for the reading guide.
- **`provider wallet sign` and `provider wallet status`** ([#112](https://github.com/full-bars/sn/pull/112), [#124](https://github.com/full-bars/sn/pull/124)): in every sn build, the release `provider` download and `:latest` as well as `:miner`. An operator can now sign the network wallet consent with this fork's own `provider`, with no 3.23-fix or meso-miner binary. `wallet sign <coldkey>` serves a local page on 127.0.0.1 where a browser wallet extension signs the consent; the page checks Host and Origin, needs a session token and expires after 15 minutes, and it sees only the public signature. `wallet status` lists the wallet entries and says whether a consent is in effect, starts later or has ended, and labels a login-proof wallet as not paying. Unlike 3.23-fix, sn keeps no local journal of the signed consent, so after a lost acknowledgement the operator signs again. Builds older than this release do not have the commands; `provider --help` shows whether yours does.
- **The one-program port: this fork's `provider` now carries the 3.23-fix operator surface** ([#100](https://github.com/full-bars/sn/pull/100)): unmodified `urnet-tools` and `urnet-docker` now drive it. It adds the hot-swap handoff, the client-JWT store with hot-restart identity reuse and the renewal watcher, the Prometheus exporter with its bind policy and control keys, the h3 limit modes (`off`, `direct`, `on`, a number or `all`) with a sticky ranking and paced relaunch, proxy grading (paid and file graders), the earnings store and per-proxy tracker with trims ranked by real earnings, the admission gate and shared auth rate limiter, profile tiers, RAM logs, the important and critical logs and `events.log`, the systemd notify, `READY` and `STATUS` handling, and the exit 75 and liveness supervision. New commands: `provider proxy paste`, `clear`, `remove --match`, `add --file` and `--url`, `add-source`, `remove-source`, `refresh`, `trim`, `summary`, `exclude`, `remove-dead` and `activity`; `provider direct`, `provider logs`, `provider print-network-id`, `provider sn-status` and `provider claim --store-client`. `provider --help` lists every command and flag.
- **Signed hotkey wallet delegation** ([#85](https://github.com/full-bars/sn/pull/85)): `provider wallet hotkey challenge`, `set` and `status` sign one consent that covers every operator, with a seed file or an externally supplied signature. `provider claim` takes exactly one credential: `--store-client=<key>`, `--provider-jwt=<path>` or `--legacy-coldkey=<ss58>`. A cleartext claim endpoint is refused before the first token request. The live hotkey calls have not been exercised against a real operator.
- **OpenRC and FreeBSD are supported** ([#92](https://github.com/full-bars/sn/pull/92), [#93](https://github.com/full-bars/sn/pull/93), [#94](https://github.com/full-bars/sn/pull/94)): `urnet-tools` has OpenRC and FreeBSD lifecycle, discovery and sysctl-optimizer backends, the Linux installer has an OpenRC branch, there is a FreeBSD installer with daily, weekly or monthly auto-update, and releases ship FreeBSD artifacts with FreeBSD and OpenRC CI. A provider supervised by OpenRC updates by service restart, not by hot swap. The [OpenRC](docs/OpenRC.md) and [FreeBSD](docs/FreeBSD.md) guides cover the setup.
- **A read-only direct-path grade and content-keyed probe sampling** ([#74](https://github.com/full-bars/sn/pull/74)): the stage-1 table probe samples a fixed hash-ordered spread of the health table instead of one contiguous block, so a region-deny gateway can no longer occupy a whole block and flip the paid verdict between A and F, and a `MinConfirmDials` floor on attempted dials gates a verdict. A separate grader dials the same table from the box's own egress and stores the result in `~/.urnetwork/direct_grade.json`, never in `proxy.state`; the grade summary and the important log gain a `direct:` line when the direct transport is on.
- **Contract lifecycle logs name the proxy** ([#105](https://github.com/full-bars/sn/pull/105)): the contract acquired lines carry the proxy identity.
- **The startup disk benchmark is exported** ([#98](https://github.com/full-bars/sn/pull/98)): `/metrics` has `urnet_disk_write_mbps`, `urnet_disk_slow` and `urnet_disk_bench_age_seconds`.
- **The upstream mainline is merged through `6608298e`** (673 commits from 2026-10-05 to 2026-10-17): the work is mostly the chain layer (settlement v2, validator intent history, mainnet checks, EVM, runtime 477 to 479 admissions, simulation testnet) plus these provider commands: `provider claim-daemon-v2` (claims an account once its claimable balance reaches `--threshold-rao`, with `--claim-now`), `provider operators`, `provider provide --all-operators`, `provider auth --operator` and `provider fleet sign`. See `provider --help` for the flags. Operators who do not run the chain tooling can ignore it.

### Fixed

- **A provider that is alive but stalled is now restarted**: a unit that sets `WatchdogSec=` is fed `WATCHDOG=1` only while the pressure monitor keeps ticking, so after 10 quiet minutes systemd restarts a provider whose garbage collector has left no goroutine able to run, and a lean start cap (60% of the running proxies) is recorded first; and the thrash watchdog counts a heap at least 1.4 times its soft limit on a box short of free RAM as severe on its own. The feed starts at READY with a 30 minute startup grace, follows the self-heal switch and the thrash restart budget (3 per 24 hours), keeps a standing cap instead of compounding it, and takes the cap back out if the stall resolves itself. A heap-runaway episode on a box without PSI now relaxes when the heap recovers. The watchdog is off unless the unit sets `WatchdogSec=`.

- **A failed renewal replaced a client identity** ([#82](https://github.com/full-bars/sn/pull/82)): when a stored client token had expired and renewing it failed, `provideAuth` minted a new client and abandoned the old client id and the history attached to it, even when the failure was only a timeout or a dropped connection. A renewal that fails without a platform verdict (a transport error, a 5xx, a 408, a 429, a cancelled context) is now transient: the identity is kept and the caller's backoff retries. A definite answer (the client does not exist, a mismatched client id, a permanent 4xx) still mints a fresh client as before.
- **`urnet-tools` did not run on Windows** ([#79](https://github.com/full-bars/sn/pull/79)): the log views ran `tail -n 20 -f`, which Windows does not have, `urnet-tools start` set the provider's working directory before the state directory existed so Windows refused to launch it, and the sudo checks had no Windows branch. The commands now run natively. A native Go follower prints the last lines and then streams new output, and it is the fallback wherever `tail` is missing. It opens the log with delete sharing, so a rotation, a clear or an update is no longer blocked by a sharing violation. If the path starts naming a different file, the follower finishes the old one and follows the new one from its start, and a truncated log is followed from its start. It also opens paths longer than `MAX_PATH`, and a 64 KiB tail window that starts exactly on a line boundary keeps its first line.
- **A stalled proxy reload could freeze the whole pool** ([#76](https://github.com/full-bars/sn/pull/76)): a reload stuck mid-body held the reloader's mutex and the cross-process lock for as long as the process lived, so every later reload and every lock-gated maintenance path went quiet. The reload slot now waits a bounded 10 minutes and skips with a loud line, a reload past 20 minutes aborts at its next phase boundary, and an overdue reload raises a critical record and a hot-restart request (gated on the `hot_restart` control key). A lock release now removes the lock file only while it still carries this holder's pid and timestamp.
- **The startup disk benchmark could take a provider down** ([#98](https://github.com/full-bars/sn/pull/98), [#99](https://github.com/full-bars/sn/pull/99)): it wrote up to 1 GB of synchronous writes before the provider reported ready. It now runs only when its answer is used, writes at most 16 MiB or 3 seconds and never more than 1/64 of free space, stays inside the state directory, refuses a disk with under 256 MiB free, skips containers unless `URNETWORK_DISK_BENCH=1`, skips a host disk that is busy, and caches the result per device. `URNETWORK_DISK_BENCH=0` turns it off. The low-disk check walks up to the root and prints nothing for a state directory it cannot measure, where it used to claim "Low disk space (0 MiB available)" for one nested more than 8 levels down.
- **The startup goroutine ramp is not judged as growth** ([#89](https://github.com/full-bars/sn/pull/89)): the diagnostics no longer read the goroutine climb during proxy authentication as a leak.
- **Proxy slots no longer share an extender identity, and both credential forms work** ([#102](https://github.com/full-bars/sn/pull/102)): each proxy slot has its own extender key file, a proxy slot no longer tries to bind the direct provider's gossip listener port, and both `user:pass@host:port` and `host:port:user:pass` are accepted even when a password contains `:` or `@`. Registered auth keys stay keyed by address, so `proxy remove` removes them and `proxy auth add` rotates the credential everywhere.
- **A version stamp blocked legacy key adoption** ([#101](https://github.com/full-bars/sn/pull/101)): the 3.23 line writes `.provider_version` into the state directory and the custody scans counted it as retained identity, so `--adopt-legacy-provider-key` was refused on the installs that need it. Both scans now skip the stamp.
- **A false "wrong network" warning cost auth codes** ([#106](https://github.com/full-bars/sn/pull/106)): the JWT notice printed on any command when a JWT existed. It now prints only when the effective API URL actually changes.
- **Bracketed IPv6 proxy hosts parse** (`65fe949ba`): the proxy address pattern is compiled once and `[::1]:1080` style hosts are read correctly.
- **The Linux installer** (same fixes as 3.23-fix): installs missing download and JSON dependencies, keeps one dependency path with a `URNET_NO_AUTOINSTALL` opt-out, uses `yum` when `dnf` is absent and keeps the root prompt off a non-interactive run.
- **`clientauth` no longer flushes the credential directory on Windows** (upstream fix, merged with the mainline).

### Changed

- **The provider's operator logs are readable sentences** ([#77](https://github.com/full-bars/sn/pull/77)): the pressure regime, pool target, trim receipt and apply, reload summary, health verdict, auth limiter and GC governor lines say what happened in plain words, with machine counters kept in a trailing `(...)` for grep. The new `[health] Verdict:` line summarizes state in one sentence. Dialer and connect lines are unchanged.
- **The container start scripts treat exit 75 as a planned restart** ([#84](https://github.com/full-bars/sn/pull/84)): `start_stable.sh`, `start_nightly.sh`, `start_jwt.sh` and the provider loop of `pelican_panel.sh` counted 75 as a crash, which counted toward the three-crash JWT clear and slept 60 seconds. It now restarts after 5 seconds and leaves the JWT alone. Every other status is unchanged.

- **`/metrics` is on by default**: the provider starts the Prometheus listener without any operator setup. The automatic bind is loopback plus the machine's Tailscale address on bare metal, and every interface inside a container only when every address it holds is private or unique-local; a container that shares a publicly addressed network stays on loopback and Tailscale instead of binding `0.0.0.0`. Override the address with `URNETWORK_METRICS=ip:port`; turn it off with `urnet-tools metrics off`. See [Monitoring](docs/Monitoring.md).
- **The unsigned wallet request is gone** ([#85](https://github.com/full-bars/sn/pull/85)): mainnet no longer accepts it. An unsigned `provider wallet set` is refused unless `--legacy-network-wallet` is given, and `provide --wallet` without a coldkey proof sets no wallet: the provider logs `subnet wallet not set: ...; continuing to provide` and keeps providing. Use `provider wallet sign` or `provider wallet hotkey` instead.
- **Dependencies**: connect moved to the `0333da84` sync base and then pinned at its Go 1.27.3 floor, and the sdk moved to current upstream ([#108](https://github.com/full-bars/sn/pull/108), [#115](https://github.com/full-bars/sn/pull/115)).

### Removed

- **The retired fleet hub's report commands and settings**: `urnet-tools report`, `urnet-docker report`, the `report-url` and `report-interval` settings, `URNETWORK_REPORT_URL`, `URNETWORK_REPORT_INTERVAL` and `URNETWORK_HEARTBEAT_INTERVAL` and the reporters behind them are gone. Nothing received the reports once the hub was removed. A saved `report_url` is ignored, so a node that had one still starts.

### Security

- **Go 1.27.3 blocks the eight compromised eMudhra intermediates (`CVE-2026-111943`)**: `go.mod`, the Dockerfile builder and every `setup-go` pin Go 1.27.3, so a binary built from this release carries the denylist. A binary built before it may continue trusting the intermediates, although an updated operating-system trust store may already reject them.

### CI

- **The VirusTotal scan covers every release artifact** ([#109](https://github.com/full-bars/sn/pull/109)): it looks up the hash before uploading, scans identical bytes once, retries 429 and 5xx honouring `Retry-After`, sends files over 32 MiB through the upload URL, and reports `INCOMPLETE` with the per-file error when an artifact was not scanned (`VT_FAIL_ON_INCOMPLETE=1` makes that fatal).
- **The installer runs on a distro matrix and gates publication**: a job runs the real installer against a fake release on Debian 12, AlmaLinux 9, Arch Linux and Alpine, plus hardening variants such as an Ubuntu-shaped host, and the release refuses to publish when it fails.
- **The two shakedown workflows run together** ([#104](https://github.com/full-bars/sn/pull/104)) with a jittered mint.

## Deploy Notes

1. **Update and restart.** An existing install picks this up on the next `urnet-tools update -f`; a Docker install pulls the new image. There is no new required setting and no migration.
2. **The certificate block needs this release.** `CVE-2026-111943` is blocked only in binaries built with Go 1.27.3. A node left on an older release may continue trusting the compromised intermediates, although an updated operating-system trust store may already reject them.
3. **Sign the wallet consent if you have not.** This release's `provider` can do it: `provider wallet sign <coldkey>` on your own computer, then `provider wallet status`. Releases up to `v2026.10.6-1064742750-meso` do not have these commands; the Quick Start shows how to check yours and keeps the 3.23-fix fallback.
4. **The unsigned wallet request is gone.** An unsigned `provider wallet set` is refused unless `--legacy-network-wallet` is given, and `provide --wallet` without a coldkey proof sets no wallet. The provider logs `subnet wallet not set: ...; continuing to provide` and keeps providing, so a start script that still passes `--wallet` does not stop a node, but it no longer sets a wallet.
5. **Remove calls to the retired report commands.** A script or cron job that runs `urnet-tools report` or `urnet-docker report`, or sets `URNETWORK_REPORT_URL`, `URNETWORK_REPORT_INTERVAL` or `URNETWORK_HEARTBEAT_INTERVAL`, now fails on the command or has the variable ignored. A saved `report_url` is ignored, so nodes that had one still start. Use `urnet-tools metrics on` and the monitoring bundle for fleet visibility.
6. **New commands on the `provider`.** The one-program port adds `provider proxy ...`, `direct`, `logs`, `print-network-id`, `sn-status` and `claim --store-client`. `provider --help` lists every command and flag.
7. **FreeBSD and OpenRC.** The FreeBSD provider and `urnet-tools-freebsd-*` assets are published from this release. Installation is in the [FreeBSD](../docs/FreeBSD.md) and [OpenRC](../docs/OpenRC.md) guides.
8. **The startup disk benchmark is bounded.** It writes at most 16 MiB or 3 seconds, skips containers and busy disks, and no longer prints a false "Low disk space (0 MiB available)" for a deeply nested state directory. `URNETWORK_DISK_BENCH=0` turns it off.
9. **Rollback is the usual one.** Keep the previous provider binary and a state tarball, stop the unit, restore the binary, start.
