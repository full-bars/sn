# v2026.11.1-1087127390-sn

Released 2026-11-01

## Quick start

> [!TIP]
> **Already running a provider?** Update in place - no reinstall, no new auth code:
> ```bash
> urnet-tools update
> ```

### Install a provider

```bash
# Linux (also Alpine and OpenRC, from a root shell)
curl -fSsL https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_Linux.sh | sh

# macOS
curl -fSsL https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_Mac.sh | sh -s -- install
```

```powershell
# Windows (PowerShell)
irm https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_Win32.ps1 | iex
```

FreeBSD is a two-step install because the installer runs with `sudo` and resolves the release tag before fetching:

```sh
fetch -qo urnet-install.sh https://raw.githubusercontent.com/full-bars/sn/refs/heads/main/scripts/Provider_Install_FreeBSD.sh
sudo sh urnet-install.sh install
```

Then authenticate once and load your proxies:

```bash
urnetwork auth
urnet-tools proxy add ~/proxies.txt
urnet-tools proxy refresh
urnet-tools status
```

> [!WARNING]
> Windows Defender flags the unsigned binaries and the PowerShell one-liner. The workaround is on the [Installation page](https://github.com/full-bars/sn/blob/main/docs/Installation.md).

### Run the container

```bash
docker run -d \
  --name=meso-miner \
  --pull=always \
  --restart=unless-stopped \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  --sysctl net.ipv4.ip_forward=1 \
  -e URNETWORK_AUTH_CODE='YOUR_AUTH_CODE_HERE' \
  -e HOST_HOSTNAME=$(hostname) \
  -v meso_miner_data:/root/.urnetwork \
  -v /path/to/proxy.txt:/app/proxy.txt \
  ghcr.io/full-bars/sn:latest
```

One image: `:latest` carries `urnet-tools` and `urnet-docker`. `URNETWORK_AUTH_CODE` is the variable the image reads; when it is set the auth-code path is selected on its own, so `BUILD` is not needed. The `:miner` image runs the same binary with a different entrypoint and is being retired.

> [!CAUTION]
> Auth codes are single-use. The token is saved to the `meso_miner_data` volume on first run, so keep that volume - without it you need a new auth code.

## What changed

### What you must do

Update and restart to get the fixes marked `[redeploy]`:

```bash
urnet-tools update
```

Nothing else needs a manual step. Auth codes and saved tokens carry over.

### Network

**An exit with no IPv6 no longer costs a dial timeout** [redeploy]. A SOCKS exit that cannot reach IPv6 only shows it by letting the dial hang. The host's own route check cannot see this, because the dial leaves from the exit. `connect` now keeps a verdict for each proxy carrier:

- After 3 IPv6 dial failures in a row through one carrier, `connect` refuses IPv6 through that carrier for 15 minutes. Dials go straight to IPv4.
- When the 15 minutes end, `connect` lets one probe dial through. A good probe clears the verdict. A failed probe starts another 15 minutes.
- One carrier's verdict never affects another carrier or the host. Exits that reach IPv6 keep using it.
- A carrier that also fails on IPv4 is a dead proxy. `connect` drops its unfinished IPv6 count.
- Only dials that name the family are judged. In the default `proxy_target_family=v4` mode, or in `proxy` mode, the exit picks the family and `connect` cannot see it. The verdict then never starts.

([#337](https://github.com/full-bars/sn/pull/337), `connect` `ca8b9020201a`)

**The extender activation request is no longer cut short** [redeploy]. The extender client capped each request at 15 seconds. The activation asks for 60 seconds. The cap ended the request in the middle of its probe. The pinned `sdk` now raises the cap to the activation budget. This comes from reading the code. No live activation has confirmed it. (`sdk` `6f4d35ee3486`)

**The `connect` and `sdk` pins moved** [redeploy]. `connect` went from `d0a4bb41c300` to `ca8b9020201a`. `sdk` went from `f17fc47e8bda` to `6f4d35ee3486`. (`12efc46ba`, `b1efe606d`)

### Tools

**`urnet-tools logs` shows the shared RAM log only to the provider that owns it** [redeploy]. When nothing else matched, it could fall back to `/dev/shm/urnetwork.log`. On a box with several providers, this showed another provider's output. One function now decides who owns the shared log. A provider with its own buffer no longer counts as a rival for the shared one. ([#334](https://github.com/full-bars/sn/pull/334))

**`urnet-tools` finds providers that run as user units** [redeploy]. A user unit with a free-form name, such as `sn-canary.service`, was never attached. Discovery judged the cgroup unit by its name. The owning user's manager decides now. `urnet-tools` no longer lists the user manager as a workload unit. If it finds no log source, the error names the paths it checked. ([#335](https://github.com/full-bars/sn/pull/335))

**The help menus point at the community Discord** [redeploy]. (`cfa578c21`)

### Installers and container

**The FreeBSD installer warns when it cannot remove the old backup** [redeploy]. After a good install, the installer removes the backup of the old binary. A failed removal used to pass without a word. Now the installer prints the path of the copy it left on disk. The install itself still succeeds. ([#338](https://github.com/full-bars/sn/pull/338))

**The nightly container updater reads the version from the release tag** [redeploy]. It used to scrape the version from an asset URL. A URL not shaped like `/download/v<tag>/` went into `version.txt` whole. Every check then downloaded the archive again. Now the updater:

- takes the tag from the release's `tag_name`;
- resets the tag on every check, so a failed probe cannot reuse the last tag;
- stops the update when the tag is empty.

This code is in `docker/scripts/start_nightly.sh`, the `BUILD=nightly` path. The auth-code path in the sample above does not run it. ([#336](https://github.com/full-bars/sn/pull/336))

### CI and docs

**The release validator accepts the `full-bars/connect` replacement** [no redeploy]. Pinned dependency mode rejected the replacement that `go.mod` now uses. The pinned module path, version and checksums are updated, with the two tests that hold them. ([#337](https://github.com/full-bars/sn/pull/337), `25f427890`)

**Docs now match the code** [no redeploy]:

- `URNETWORK_NODE_NAME`, `URNETWORK_PROXY_BENCHMARK`, `URNETWORK_PROXY_BENCHMARK_ENDPOINT`, `URNETWORK_ADAPTIVE_GC` and `URNETWORK_SHM_LOG` are marked "not implemented". No Go code reads them. Setting them changes nothing.
- `URNETWORK_PUBLIC_IP` is set by the Docker startup scripts. No Go code reads it.
- The [Node Identity](https://github.com/full-bars/sn/blob/main/docs/Node-Identity.md) page says the same about node labels, `urnet-tools rename` and `show-ip`.
- The Docker page says vnStat is on by default. The container listens on port 8080 unless you set `ENABLE_VNSTAT=false`.
- The Docker page says the Prometheus `/metrics` endpoint is a separate listener and is on by default.
- The duplicate page `urnet-tools-Go.md` is gone. It differed from `urnet-tools-go.md` only by case.
- The extender page and the log reference show the cause text of a failed activation. The FreeBSD page says the platform refuses durable client registration.
