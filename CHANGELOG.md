# Changelog

Releases of this fork are tagged `v<YYYY.M.D>-<build>`, where the build number derives from the tagged commit's time. Releases before 2026.10.22 carried a `-meso` suffix. Upstream (`urfoundation/sn`) publishes tags in the same shape, so the newest entry below the unreleased list, not the tag list, is the latest release of this fork.

## [Unreleased]

Everything below merged after `v2026.10.22-1078667780`. The miner is the program this fork ships; entries about the relay `provider` say so.

### Added

- **The activation budget charges a pass for the families the host can reach** ([#262](https://github.com/full-bars/sn/pull/262)): the budget charged every host two posts per activation pass, so a box without usable IPv6 spent two of the five posts it allows itself in the operator's six-per-hour window and got two passes where it could have had five. The host is measured at startup with a one-byte IPv6 send, because a dial succeeds on a blackholed route and the egress probe was changed to send for the same reason, and the result is stored in `provider_state.db`. It is re-measured on a cadence that follows what the host has shown: every 15 minutes while IPv6 works or was lost inside a day, every 6 hours when it has never had it, and immediately whenever the interface address list changes. A refusal backoff now stops growing at the operator's hourly window instead of six hours, and a streak that goes quiet for a day starts over. `urnet-tools status` prints the measurement as `host capability: ipv4 only (checked just now; never had ipv6)`.
- **The log names the identity and stops repeating itself** ([#249](https://github.com/full-bars/sn/pull/249), [#250](https://github.com/full-bars/sn/pull/250)): a start with 465 unreachable identities printed one control-plane warning, one ack-lifetime expiry and two token-refresh lines per identity. The control-plane warning is now one tally per wave (count, oldest wait, sample of addresses) that repeats an unchanged count at most every five minutes; an auth refusal for a recoverable legacy key ends with the command that fixes it; a `[startup]` summary follows the first heartbeat; `[proxy][udp]` lines name the slot and the action; every `[api-token]` line carries `client=<id>`; and a gossip node prints one startup line naming its peer, network and role. `reason=ack_lifetime` sequence exits moved to `-v` with every field intact, because an expiry is the ordinary outcome for a destination with no route.
- **Authentication backoff and a terminal stop**: a start whose every slot fails with a credential rejection or a rate-limit refusal records the streak in `<state>/auth_backoff.json`, waits 60 seconds from 10 failures and 300 from 20, and stops with exit 79 once 30 failures span two hours. The unit sets `RestartPreventExitStatus=79`, which reaches existing nodes when the unit is redeployed; without it the node keeps retrying on the backoff schedule.
- **The direct slot runs alongside the proxies** ([#256](https://github.com/full-bars/sn/pull/256)): a run with proxies served only from them, so the host's own address was idle and the extender role, which only the direct slot can hold, was never claimed on a proxy node. The direct slot is now appended to the launch list when direct providing is on, last so each proxy keeps its index; `direct off` still leaves the proxies alone. An extender binds tcp 443 and udp 443, which an ordinary user cannot do while `net.ipv4.ip_unprivileged_port_start` is 1024, so an extender node needs that set to 0 (persisted under `/etc/sysctl.d/`) or a root unit.
- **A proxied slot can prove IPv6 when its proxy carries it** ([#237](https://github.com/full-bars/sn/pull/237)): a slot whose proxy has proven v6 egress runs one extra transport pinned to v6 through that same proxy, so the identity is recorded dual-stack instead of IPv4-only. The pin is asked for only after a staged probe proves the proxy's v6 path.
- **A proxied identity runs one family-agnostic transport** ([#232](https://github.com/full-bars/sn/pull/232)): this is the shape production 3.23 runs. A pinned transport dials from the host and cannot leave a SOCKS proxy, so the proxied identity had no route to the platform on v6; the direct identity keeps the v4/v6/standby group.
- **An IPv6 probe classifier and verdict ledger** ([#231](https://github.com/full-bars/sn/pull/231)): pure building blocks, not yet wired into a dial path. One SOCKS5 CONNECT outcome becomes a yes, no or unknown verdict for "can this proxy carry IPv6", and a per-proxy ledger persists it with trust windows.
- **The probe records the measured dial cost** ([#224](https://github.com/full-bars/sn/pull/224)): the grader scored reachability and interception only, so a pool with a 1.6 second median dial still reported `scores: median 1.00, p95 1.00`. The probe now keeps the measured cost beside the grade.
- **A miner CLI that explains itself** ([#160](https://github.com/full-bars/sn/pull/160)): the sync with `urfoundation/sn` brings a one-screen overview for a bare `provider`, `--help` and `help`, per-command help (`provider help wallet`), `did you mean` suggestions for typos, one-line errors instead of panic traces at a terminal (`-vv`, `PROVIDER_DEBUG=1` or a non-terminal stderr keep the trace), and the aliases `start`, `login` and `network`. On top of it sit `provider setup`, `status` (with `--json` and exit codes 0, 3 and 4), `doctor` (state folder mode and owner, DNS, connection, TLS roots, clock skew, whether updates can install), `service` (install, uninstall, start, stop, restart, status and logs as a systemd user or system unit or a launchd job, with a timer running `provider update --auto` every 6 hours) and `update` (digest check, one-rename swap, rollback). `start` refuses a device that was never signed in. `service` and `setup` refuse to start a second miner on one state folder, and `update` run as root refuses a binary or state folder another user can change. On Windows the same commands work, the wallet consent store has native custody, and `service install` writes a Startup shortcut that runs a hidden supervisor with restart on failure and an update check.
- **`provider update` follows this fork and installs only the miner archive** ([#160](https://github.com/full-bars/sn/pull/160)): the default update source is `full-bars/sn` instead of upstream's build releases, so the automatic timer can no longer replace a fork binary with upstream's. The release workflow now publishes `urnetwork-miner-<tag>-<os>-<arch>.tar.gz` for all eight platforms, and the update takes only that archive. The `urnetwork-provider-*` archives hold the relay and are never installed over the miner. `URNETWORK_UPDATE_URL` still overrides the source. The previous release has no miner archive, so this is the first release `provider update` can install from.
- **`provider fleet init` and diagnostics sinks from the sync** ([#160](https://github.com/full-bars/sn/pull/160)): `provider fleet init` builds a canonical fleet manifest, regular files and macOS terminals are admitted as diagnostic sinks, and diagnostics reach Windows consoles and pipes. The same sync carries upstream's runtime 481 to 484 admissions and release-gate work in the chain layer, none of it in `miner/` or `provider/`.
- **Operator surfaces: an action ledger, pprof, resource warnings and memory headroom** ([#207](https://github.com/full-bars/sn/pull/207)): `<state>/autopilot.jsonl` is now written, so the control socket's `ledger` command and `urnet-tools autopilot log` show what the miner decided: OOM-cap reduce, relax, clear and frozen, the kill switch forgetting a cap, thrash restarts and refusals, and trim applications at launch and on a running pool. `URNETWORK_PPROF=127.0.0.1:6060` starts a pprof listener (off by default) that accepts only a literal loopback IP and port, so a heap dump cannot be published on every interface; a HotSwap candidate retries the bind until its parent lets go. Startup logs one `[proxy][resources] warning:` line per mismatch between the Go soft limit, the box's RAM ceiling and the heap the pool needs, and changes nothing. A persisted `set gomemlimit` or `set gogc` is now replayed at startup, where a restart used to lose it to the memory plan's default. The pressure tick logs when free memory falls under 10% of RAM (clamped to 150 to 400 MiB) and when it recovers, observation only.
- **Profit, billable, contract, heartbeat and pool-health observability** ([#209](https://github.com/full-bars/sn/pull/209)): the miner writes `<state>/billable_rate` every 10 seconds, so `urnet-tools idle-update` can tell a lull from a missing metric, and logs a `[profit]` line every 15 seconds. The billable and settled series, structural zeros until now, are fed from each slot's SDK readings: `urnet_billable_bytes_total{direction}` counts relay bytes and `urnet_contract_used_bytes_total{direction}` counts the engine's per-contract accounting, so their difference is the drift this node carries. `urnet_contracts_total{result="acquired"}` and the gauges `urnet_contracts_open`, `urnet_contract_limit_bytes`, `urnet_contract_used_bytes` and `urnet_contract_utilization` come from the SDK's contract feed. There is no `denied` series, because the pinned SDK exports no denial event and a zero would claim nothing was refused. A `[health]` heartbeat runs every `URNETWORK_HEALTH_INTERVAL` (5 minutes by default, 1 minute floor) and writes a `heartbeat:` block into `proxy_health.state` with `at`, `uptime`, `interval` and `stale_after`. `urnet_proxy_pool_up_floor`, `urnet_proxy_pool_degraded_ticks` and `urnet_proxy_pool_scope{scope="none"|"isolated"|"pool"}` say over a one-hour window whether the pool failed as a unit or a few members did, and are omitted when the pool is empty.
- **Incident capture, a host audit and persistent error counts** ([#205](https://github.com/full-bars/sn/pull/205)): a redacted evidence bundle (at most 2 MiB, 512 KiB per file, 48 files, 2 seconds) is taken on a recovered worker panic, a fatal exit, a hotswap that could not hand over, an OOM-cap action at startup and a thrash escalation. Credential-shaped state is listed by name, size and mode and never copied. A read-only startup audit grades the soft file-descriptor limit, `nf_conntrack_max` against the target `urnet-tools optimize` writes, and the established-connection timeout; `URNETWORK_SKIP_AUDIT=1` skips it and no finding can stop a launch. `urnet_lifetime_errors_total` now appears in the scrape, backed by `<state>/error_counts.json` and an allow-list of diagnostic codes.
- **One smart-dialer scheduler, switchable live** ([#214](https://github.com/full-bars/sn/pull/214)): a single dispatcher replaces a goroutine, context and timer per proxy identity (the PR measures 2000 identities going from 2000 goroutines, contexts and timers to one goroutine and one timer), and probes an egress path once however many identities share it. `set smart_dialer on|off` now takes effect without a restart and off allocates nothing. A path serving clients is skipped, and probing is limited to 2 in flight, one connect per second and 1200 probes per hour. The measured order is not persisted, so a restart re-measures.
- **The startup disk audit runs, with a time-budgeted sample** ([#171](https://github.com/full-bars/sn/pull/171), [#216](https://github.com/full-bars/sn/pull/216), [#218](https://github.com/full-bars/sn/pull/218)): the audit was ported complete but nothing called it, so the three `urnet_disk_*` series were never populated. It now starts once before the providers run. The write loop used to stop at 16 MiB, which an NVMe finishes in about 20 ms, so the published rate was a burst figure. A 3 second budget and a 256 MiB ceiling govern now: a microSD still writes about 20 MiB, an eMMC about 240 MiB, an NVMe hits the ceiling. The log line carries the sample length, for example `900.0 MB/s (256 MB written in 85 ms)`. Containers still skip the benchmark unless `URNETWORK_DISK_BENCH=1`, and a host under IO pressure still skips it. The cached result now records its sampling shape, so the first start after the update benchmarks again.
- **Proxy add, remove and rotation reach the running pool** ([#187](https://github.com/full-bars/sn/pull/187)): the miner wrote a reload trigger on every change and nothing read it. A watcher now polls it every two seconds, starts new identities, stops removed ones and rotates an identity whose password changed. Adding a second identity at an address another identity owns is refused with a message, because it would re-identify the running slot.
- **Alive-but-poor proxies are reaped** ([#188](https://github.com/full-bars/sn/pull/188)): a mirror of the relay's degraded reaper, with the same keep-count math, ranking, re-verify and minimum down time. A reaped identity is held out of the desired set and released after the hold. It stands down while the auth outage signal is frozen and skips timeout-family failures.
- **Proxy-leg evidence, contract identity and the UDP relay check** ([#161](https://github.com/full-bars/sn/pull/161), [#170](https://github.com/full-bars/sn/pull/170), [#201](https://github.com/full-bars/sn/pull/201)): a proxy that passes login but cannot reach the platform is counted as `proxy-leg` (`urnet_proxy_leg_failures`, `proxy_leg_failures` in `proxy.state`), kept apart from `auth_failures` because the two drive different remedies, and a shadow sweep flags it after five failures in ten minutes only while another path reached the platform in the last five. Nothing is shed. Contract lines name their path as `proxy[slot] (address)`. A SOCKS5 UDP association, compared against the TCP-side address, stores one verdict per identity (ok, no-relay, exit-mismatch, unknown), H3 requires an admitting verdict, and losing one relaunches the identity on H1 only. A proxy that authenticates and then loses its relay is marked `recently_offline` and counted in `urnet_proxy_transport_drops`, after a 10 second confirmation window.
- **Relay-port behaviours in the miner** ([#167](https://github.com/full-bars/sn/pull/167), [#168](https://github.com/full-bars/sn/pull/168), [#169](https://github.com/full-bars/sn/pull/169), [#173](https://github.com/full-bars/sn/pull/173), [#174](https://github.com/full-bars/sn/pull/174), [#175](https://github.com/full-bars/sn/pull/175), [#177](https://github.com/full-bars/sn/pull/177), [#195](https://github.com/full-bars/sn/pull/195)): URL-sourced slots hold until the curated ramp starts or a five-minute grace passes, and a slow-auth requeue retries after 30 seconds, where the old ramp step took over an hour; a stale self lock left by a hotswap exec is cleaned. A swap-thrash watchdog senses PSI, swap, refaults and direct reclaim, and escalates through a thrash cap and a supervised exit 75 restart, plus a liveness watchdog. A host pressure sampler feeds the pacing decisions that previously read calm forever. A baseline sampler writes `<state>/baseline.jsonl` every 15 minutes (`URNETWORK_BASELINE_INTERVAL`, one minute floor), switchable with `set baseline off`. Lifetime totals persist in `<state>/lifetime_metrics.json` with a recorded start (`urnet_lifetime_start_timestamp_seconds`, `urnet_lifetime_start_approximate`), and an unchanged counter store is no longer rewritten every 45 seconds. `oom_cap` works: after a kernel OOM kill the next start opens 80% of what was running, floored at 50, at most three reductions per 24 hours; the default mode is `shadow`.
- **Systemd status line** ([#172](https://github.com/full-bars/sn/pull/172)): `systemctl status` shows how many proxies are launched, up, parked or paused.
- **Panic containment** ([#189](https://github.com/full-bars/sn/pull/189), [#197](https://github.com/full-bars/sn/pull/197)): a panic in a manager loop (URL fetcher, reaper, pressure monitor, pool controller, grader, audit, baseline and others) restarts that loop with a backoff from 1 second to 5 minutes instead of ending the process; `urnet_loop_up` and `urnet_loop_restarts_total` are in the scrape. The remaining bare goroutines are contained or supervised, and a `[panic] recovered in <name>` line says which one died.
- **`urnet-tools install-service` for OpenRC and FreeBSD** ([#165](https://github.com/full-bars/sn/pull/165)): with `--user`, `--binary` and `--dry-run`, it writes an OpenRC init script or a FreeBSD rc.d script atomically and enables it, and refuses a root service user. FreeBSD uninstall now disables the rc.d service.
- **The trim cap is visible** ([#151](https://github.com/full-bars/sn/pull/151), [#163](https://github.com/full-bars/sn/pull/163)): with no argument `urnet-tools proxy trim` reports the effective cap and its source (operator, OOM or thrash), the configured pool size before the cap, how many proxies the cap holds back and the live counts, and `urnet-tools status` carries a `trim` row whenever a cap applies. Trim state is reported only from a complete pool, so an unreadable `proxy_url.json` cannot understate it.
- **The extender keeps its lag.dev measurement key beside its identity seed** ([#158](https://github.com/full-bars/sn/pull/158)): the extender role writes a PEM private key to `.provider.extender.measurement.key` in the state directory when the file is absent (mode 0600, direct slot only). Back it up with the rest of the state directory and treat it as secret.
- **The lifetime counters say when they began** ([#152](https://github.com/full-bars/sn/pull/152), [#155](https://github.com/full-bars/sn/pull/155)): the relay `provider` persists a start stamp written once, its `all-time` lines carry it, a pre-existing store reports an approximate start instead of inventing a date, and its scrape gains `urnet_lifetime_start_timestamp_seconds` and `urnet_lifetime_start_approximate`.
- **Proxies that pass login but cannot reach the platform are counted in the relay `provider`** ([#159](https://github.com/full-bars/sn/pull/159)): `proxy-leg:N` on the `[health][proxies]` line and `urnet_proxy_leg_failures` in the scrape, with a shadow decision that logs `[proxy][shed] shadow: would shed ...` and counts `urnet_proxy_leg_shadow_shed_total`. Shadow only.
- **A parity check for relay behaviour with no miner counterpart** ([#196](https://github.com/full-bars/sn/pull/196), [#208](https://github.com/full-bars/sn/pull/208)): `go run ./scripts/parity-check` lists the relay files and declarations the miner lacks, exits 0, 1 or 2 so CI can use it, and validates its function and type mappings.

### Fixed

- **`urnet-tools version` warns when the tool and the provider are different engines** ([#261](https://github.com/full-bars/sn/pull/261)): a version string cannot identify a lineage, because this fork and the 3.23-fix lineage both stamp date-epoch builds, so a tool built for one engine looked like ordinary drift beside a provider from another. The report reads the module path out of the provider binary and compares it with its own, names both lineages and prints the exact download of the tool asset from the provider's own release. It never replaces its own binary: a failed verification on an unattended host would leave no tool and no path back.
- **The state store owns only state that has no legacy file** ([ab8d4e2cb](https://github.com/full-bars/sn/commit/ab8d4e2cb170db1f80dbcf9bba6044ecc2939ba8)): `provider_state.db` imported `auth_backoff.json` and renamed it, which broke a host switched back to an older engine, because that engine found no file, wrote fresh defaults, and the next start of this engine adopted them over good state. The store now holds only state this engine introduced, legacy files stay exactly as they were, and nothing is imported, quarantined or archived.
- **An all-slots-failed run exited 0** ([#246](https://github.com/full-bars/sn/pull/246)): a `provide` run whose every slot failed authentication returned normally, which `Restart=on-failure` never restarts, so the node stayed down until someone noticed. It now exits 1 when no slot authenticated and every launched slot ended with an error while the context is still live; partial failure and a clean stop are unchanged.
- **The systemd watchdog had two feeders, one ungated** ([#241](https://github.com/full-bars/sn/pull/241)): the ungated ticker from #223 re-armed the watchdog while the gated liveness loop withheld its ping, which is the only thing that makes systemd restart a hung provider. The ticker now hands over to the gated loop.
- **A `Type=notify` unit restarted before it reached active** ([#230](https://github.com/full-bars/sn/pull/230)): `notifySystemdReady` had no caller, so the unit stayed `activating` and systemd killed it at `TimeoutStartSec`. READY=1 is now sent once startup is complete.
- **`[health]` reported a healthy pool this process had not verified** ([#229](https://github.com/full-bars/sn/pull/229)): `up` came from the persisted grade, so a restart showed 300 to 400 proxies up within a second with zero registrations and 483 slots that had only reused a stored JWT. The line now counts control dials this process made.
- **The RAM log trim held the writer's lock** ([#233](https://github.com/full-bars/sn/pull/233)): the rewrite is in place with `Truncate` and one `Write` on the same descriptor, so `tail -f /dev/shm/urnetwork.log` and `provider logs` keep following the same inode.
- **A fresh container could not create its provider key** ([#239](https://github.com/full-bars/sn/pull/239)): `start_stable.sh` launched `provide` without `--allow-client-registration`, so the custody gate refused on an empty state dir and the container stayed `Up` with a valid JWT and no provider. It now passes the flag.
- **The probe table carried reputation-class hosts** ([#238](https://github.com/full-bars/sn/pull/238)): `www.reddit.com` and `www.stackoverflow.com` were probed from provider egress, the traffic pattern that gets an address listed. They are replaced with `connectivity-check.ubuntu.com` and `speedtest.tele2.net`.
- **Provider fixes from running the miner as a real provider** ([#223](https://github.com/full-bars/sn/pull/223)): the systemd notify helpers had no callers, import adoption and probe accuracy were fixed, and the carrier-count change was dropped as neutral because the platform budget is per identity and bound by bytes.
- **A silent platform edge cost proxied-H3 miners about 16 Mbit/s with nothing to throttle it** ([#219](https://github.com/full-bars/sn/pull/219)): the pinned `full-bars/connect` has no reconnect budget, so with `h3` set to `all` or a count every carrier of every proxy redialed on its own timer for as long as the outage lasted. One node on `h3 all` spent a flat 15.5 to 16.4 Mbit/s for about 15 hours of the 2026-10-23 outage, roughly 30 times more tx than rx. The miner now sheds the dials: while the miner's own outage signal reads the platform as unreachable, no proxied identity is eligible for the fallback transports. The signal counts sign-in outcomes in one-second buckets and calls an outage when 90 seconds hold at least 12 failures and not one success, after it has been watching that long, so a start-up stampede of slow first sign-ins is not mistaken for one. It is separate from the reaper's detector on purpose: that one guards blacklisting, which is destructive, so it waits five minutes and clears on a single success anywhere, while shedding H3 is cheap and reversible and should not wait. The relaunch pass restarts the affected identities a few at a time and never one with a client, H1 keeps probing the platform, and the direct identity keeps its H3. H3 comes back only when the signal reads as recovered, which takes at least 5 successes and a majority of attempts succeeding over two minutes, held for two more, so one sign-in among hundreds of failures does not restore it. It is then given back one identity every 3 seconds, because this miner has no reconnect budget to meter a relaunch of every identity just as the platform returns. The first 90 seconds of an outage still leak.
- **The URL reaper judged proxies during a platform outage** ([#185](https://github.com/full-bars/sn/pull/185), [#186](https://github.com/full-bars/sn/pull/186)): on 2026-10-23 the degraded reaper dropped 249 of 498 proxies as under-performing while the platform was unreachable. A reaper cycle where every probe failed at the API stage while a tunnel was up no longer demotes anyone. The pinned connect exports no outage signal, so the miner derives one from its own auth stream: a pool-wide run of at least 5 failures with no success for 5 minutes freezes the reaper and the give-up ladder, and any success clears it. The verdict is deferred, not erased. `PROXY_OUTAGE_FREEZE_WINDOW` and `PROXY_OUTAGE_FREEZE_MIN_FAILURES` override the window and floor, and an invalid value falls back to the default. The relay `provider` holds a round off when its scores carry no ranking.
- **`direct off` kept serving from the direct IP** ([#190](https://github.com/full-bars/sn/pull/190)): the toggle was read only by the grader and the startup path. The run now owns the direct slot, cancels it when the toggle goes off and parks instead of exiting. Startup now obeys a persisted `off`, which is a change for a direct-only node after a restart. A capture-profile run still needs a restart.
- **`set h3` reconnected identities without changing the transport** ([#193](https://github.com/full-bars/sn/pull/193), [#202](https://github.com/full-bars/sn/pull/202)): the relauncher and the launch record had no production caller, and the policy that `h3ModePreferences` builds was never applied, so turning H3 off cost a reconnect and left QUIC running. A mode change now relaunches the identities that moved and hands the policy to the SDK. The SDK swaps carriers make-before-break, so a short window on the default policy remains, and the write is read back. `set h3` now genuinely stops QUIC where it did not; try it on one box before a fleet rollout.
- **Proxied QUIC could leave from the node's own address** ([#200](https://github.com/full-bars/sn/pull/200)): the miner never installed the SOCKS5 UDP packet-connection factory the relay installs, and the bandwidth wrap dropped the field, so the platform QUIC dial and the alt-H3 and alt-whodis API dialers (which carry the JWT) used the host socket. Both paths now go through the proxy, the direct slot never gets a factory, and a proxy that cannot relay H3 falls back to a TCP carrier through it.
- **Pressure shedding reported shedding it did not do** ([#192](https://github.com/full-bars/sn/pull/192)): it logged a shed and lowered the persisted target while every slot kept running. Shedding now cancels through the reloader's registry and persists only what it cancelled.
- **The audit graded and reported but did not act** ([#194](https://github.com/full-bars/sn/pull/194)): client counts were always `unknown` and the park cancel map was never populated. Rules now read the identity-keyed bandwidth counters, and a park cancels the slot and holds it out until `proxy audit release`.
- **Four places where the miner reported what it did not do** ([#198](https://github.com/full-bars/sn/pull/198)): `proxy_traffic.state` was always an empty table; per-proxy series missed any proxy with credentials; one log line printed `2 prox2 ies`; and a planned thrash restart (exit 75) was reported as a rejected sign-in.
- **Docs, help and the metric surface claimed more than the code did** ([#199](https://github.com/full-bars/sn/pull/199)): `node_name` and `ip_version` are accepted and persisted but nothing reads them, and `h3_datagram` has no toggle in the pinned connect; the control reply now carries `effect=live|restart|none`. Metric seams with no source are marked unsupported instead of publishing zeros. The deferred critical log is now flushed every 30 seconds and at shutdown, where late lines were never written.
- **The default memory plan could set a soft limit above physical RAM** ([#203](https://github.com/full-bars/sn/pull/203)): the per-provider floor was applied before multiplying back out, so 2000 providers on 8 GiB got a 117 GiB limit. The limit is clamped to the usable host heap (4/5 of RAM) and an over-subscribed plan logs a `[mem] over-subscribed` line. `--max-memory` is unchanged.
- **A hung state directory could stop the miner from restarting** ([#210](https://github.com/full-bars/sn/pull/210)): the liveness self-exit logged to `events.log` in the directory whose hang fired it. It now uses a bounded stderr note. A released hold could also leave a proxy invisible to the reaper; the down-since clock now restarts whenever it is unset.
- **The transport-drop series lagged a confirmed drop by up to 60 seconds** ([#208](https://github.com/full-bars/sn/pull/208)): `urnet_proxy_transport_drops` now overlays the live health registry.
- **The relay `provider` ran an idle smart-dialer goroutine per proxy** ([#204](https://github.com/full-bars/sn/pull/204)): nothing is allocated while the preference is off, `smart_dialer` is restart-required in the relay, and the gateway hold is keyed by identity so a reload that renumbers slots cannot lock a slot out for up to two hours.
- **URL proxies were held back for an hour behind proxies that never authenticate** ([#157](https://github.com/full-bars/sn/pull/157)): the warmup gate released on a ratio over every registered proxy, so a dead tail never crossed it and only the 60-minute backstop ended the hold. The relay fetcher's wait is now bounded to five minutes and the reload fires when the grace expires.
- **The registration custody repair hints failed on non-English Windows** ([#146](https://github.com/full-bars/sn/pull/146)): the refusal messages named `SYSTEM` and `Administrators`, which icacls cannot resolve on a localized system. The grants now use the well-known SIDs (`*S-1-5-18`, `*S-1-5-32-544`).

- **A built-in baseline recorder** (<https://github.com/full-bars/sn/pull/42>): every provider keeps a small local record of its own behaviour in `~/.urnetwork/baseline.jsonl`, on by default and with no setup, so an upgrade can be judged against what the box did before it. Counts and totals only, never proxy addresses, usernames or passwords, and an unmeasured field is omitted rather than written as zero. `urnet-tools baseline show|mark|compare` reads it, the comparison derives its rate from the lifetime counter's delta, excludes the ramp after every start from both sides, and warns when capacity changed. `set baseline off` stops recording without a restart and keeps the file. It starts with this release, so there is no earlier record on a box upgrading from an older one. See [Baseline recorder](docs/Baseline.md).
- **H3/QUIC now travels through the proxy** (<https://github.com/full-bars/sn/pull/34>): an identity that won the H3 race used to reach the platform from the host's own address, because the transport opened a UDP socket on the host. QUIC is now relayed through the identity's SOCKS5 proxy with a UDP association, so the platform sees the proxy's address. The proxy's real address plus its reported port is the relay, and the reported address is never trusted. Only datagrams from the relay are accepted, the association ends with its control connection, and a proxy that will not relay UDP is an error rather than a fallback to a host socket, so the transport falls back to a TCP mode through the proxy. See `provider/h3_packet_conn.go`.
- **The proxy's UDP path is checked before H3 uses it** (<https://github.com/full-bars/sn/pull/34>): the grade and MITM probes only see the TCP path. Before H3 goes through a proxy's UDP relay, the relay is checked once per identity. It must answer, and the address a STUN server sees through it must equal the address an address service sees over TCP through the same proxy. A dead relay or a different exit disables H3 for that identity. The result is keyed by proxy identity, remembered for 30 minutes, limited to 8 concurrent checks, and forgotten after two lifetimes. See `provider/proxy_udp_check.go`.
- **The smart dialer probes every transport in the background** (<https://github.com/full-bars/sn/pull/35>, <https://github.com/full-bars/sn/pull/61>): the provider measures every transport with background probes and chooses a transport from the measured cost. The probe runs only after auth, behind a global limiter that yields to auth, and the log carries the numbers behind the choice.
- **The self-management stack, ported from the mature fork** (<https://github.com/full-bars/sn/pull/38>): `urnet-tools` gains the autopilot, oom-cap and smart-dialer controls, and the provider records its own actions in an action ledger.
- **Dashboards and alerts get the metric families they query** (<https://github.com/full-bars/sn/pull/41>): the provider exports the families the Grafana dashboards and alert rules read, so the panels no longer depend on a removed producer.
- **Host observability and host memory** (<https://github.com/full-bars/sn/pull/48>, <https://github.com/full-bars/sn/pull/49>): the provider records GC state, conntrack fill and TCP socket states, and it reads host memory on Windows and macOS as well as Linux.
- **The H3 identity set and QUIC DATAGRAM are gated by live control keys** (<https://github.com/full-bars/sn/pull/66>): the `h3` setting chooses which identities run H3. It takes `off`, `direct`, a proxy count, or `all`. It applies to the running provider with no restart. `on` is an alias for `direct`, and `0` aliases `off`. The default is `all`, which is what sn did before this setting existed. A change reconnects only the identities that join or leave the set. A bare integer caps the proxy set only. The direct identity is always additionally eligible and never consumes one of the N. So `h3=10` runs ten H3 proxies plus the direct identity. Two settings gate QUIC DATAGRAM. `h3-datagram` gates the receive and offer lane. `h3-datagram-send` gates the send lane. Both default off and both apply live. The offer is read at H3 dial, so a change re-dials the connection. The send threshold is read per message, so a change is immediate. One predicate, `snH3Eligible` in `provider/h3_mode.go`, decides eligibility. The `[health]` line carries `h3=<mode> h3_set=<n> h3_proxies=<m>` and the datagram counters. `/metrics` carries `urnet_h3_mode_info`, `urnet_h3_set_size`, `urnet_h3_proxy_set_size` and the `urnet_h3_datagram_*` families. The offered, accepted and blackhole counters are not exported, because the pinned connect revision cannot count them. See `docs/Configuration.md` and `docs/Monitoring.md`.

### Changed

- **The dropped bucket is labeled on its own, and the idle hint reads again**: the live status and `top` view called the was-up-now-down bucket `down`, the same word the whole-pool figure uses for dead plus dropped. The breakdown bucket is `dropped` now, matching the proxy health report, so `down` has one meaning. The idle hint no longer calls every offline proxy dead. Labels and wording only; the reaper inputs are unchanged.
- **A node that deliberately runs with no proxies now reads `active`, not `degraded`** (<https://github.com/full-bars/sn/pull/31>): serving on the direct transport with no proxy source configured is a valid, completed configuration, and was previously indistinguishable from a real outage. A configured source that came back empty still reads degraded, and so does a node whose direct transport is off with nothing to serve.
- **The idle hint blames auth only when it explains the idleness** (<https://github.com/full-bars/sn/pull/31>): a steady trickle of auth retries on a large healthy pool is no longer reported as an auth outage. Auth is blamed for a failure wave, or when most of the pool is not connected while failures are happening; otherwise the hint states what is true and shows the numbers behind it.
- **The reload summary says where additions came from** (<https://github.com/full-bars/sn/pull/31>): the `reloaded: +N added` line breaks the additions down by source, and URL-sourced launches get their own line instead of being folded into a bare count.
- **Proxy keys are never printed raw** (<https://github.com/full-bars/sn/pull/30>): an identity key embeds the account, so operator-facing listings show a display form instead of the raw key.
- **The build uses upstream modules instead of the stale forks** (<https://github.com/full-bars/sn/pull/36>, <https://github.com/full-bars/sn/pull/37>): `sdk`, `glog`, `goidenticons`, `server`, `warp`, `operator-proxy`, `proxy` and `userwireguard` now resolve to the upstream `urnetwork` modules instead of the fork's own copies.
- **The `connect` pin moves to the 5 October build** (<https://github.com/full-bars/sn/pull/54>, <https://github.com/full-bars/sn/pull/55>, <https://github.com/full-bars/sn/pull/56>, <https://github.com/full-bars/sn/pull/60>, <https://github.com/full-bars/sn/pull/64>, <https://github.com/full-bars/sn/pull/65>): the pin advances several hundred engine commits, and it carries the retrying out-of-band contract send, the contract verification reason log, the unconditional successor pre-buy, and the canceled-dial classification.
- **H3 datagram gating changes the datagram default, a change from the previous silent default** (<https://github.com/full-bars/sn/pull/66>): before this release sn offered QUIC DATAGRAM silently and by default. It built from connect's own settings, and nothing in `provider/` overrode it. The pinned library had no send gate, so small frames also went out as datagrams on their own. Now both lanes are gated, and `h3-datagram` and `h3-datagram-send` default off. After an upgrade an H3 connection no longer offers DATAGRAM unless you turn it on. Run `urnet-tools set h3-datagram on` to offer it. Both keys apply live.
- **Proxy health now says `down`, `dropped` and `never up` in place of `degraded` and `dead`** (<https://github.com/full-bars/sn/pull/67>): the proxy health report headline shows `down` as one total with its two parts named beside it, `dropped` for a proxy that was up and then went down, and `never up` for one that never connected, instead of the old `Dead` and `Degraded` pair that double-counted the dropped bucket inside `Down`. The report `STATUS` column and the `proxy_health.log` rows say `DROPPED` and `NEVER UP`. The `top` view and the live status block say `down` in place of `degraded`. The snapshot state reason reads `N of M proxies down`. The report and the `top` view now agree on the word. The behaviour and the proxy pruning are unchanged: the reaper predicate and every internal identifier are byte-for-byte identical, and `degraded` stays for the systemd status band that measures how much of the pool is live. See [Proxy management](docs/Proxy-Management.md) and `LOG_REFERENCE.md`.

### Fixed

- **A proxy-pool reload now re-applies the H3 identity set** (<https://github.com/full-bars/sn/pull/69>): a reload that re-resolved the `h3` cap stored the new resolution but never re-applied it to the running proxies, so a proxy displaced from the top N kept running H3 and a promoted proxy stayed on H1. The reload now re-applies the resolved set on the path `SetH3Mode` uses, so a proxy starts or stops H3 as soon as it enters or leaves the cap, instead of waiting for the next control change. The mode swap is also a compare-and-swap against the pointer that was read, so a concurrent control update such as `h3 = off` is no longer overwritten by a stale re-resolve, and the re-resolve is a no-op when the eligible set is unchanged.
- **Billable bytes were the socket byte count, so they always equaled total** (<https://github.com/full-bars/sn/pull/62>): the connection wrapper incremented billable and total by the same amount, which made billable the bytes on the relay-egress socket (and, when H3 won, the tunnel too), not the traffic relayed for clients. Billable now comes from the engine's own relay accounting for each proxy (`RemoteIngressByteCount` as `BillableTx`, `RemoteEgressByteCount` as `BillableRx`), the same IP-packet bytes the previous stable release line counts in its user NAT provider. Expect a step DOWN in billable, in the billable rate, in the earnings ranking that the trim reads and in the Grafana billable panels at deploy: benchmark, probe and H3 tunnel bytes no longer count. The platform's own payout is unaffected. Total is now every byte on the sockets that go through the proxy: relay egress, the provider's own API, auth and H1 tunnel connections (counted by a total-only wrapper that never touches clients or billable, and leaves a direct identity's dial untouched), and the H3 tunnel socket when H3 wins, the same quantity the previous stable release line reports; expect total to step UP at deploy. The platform's own per-contract usage is exposed as `urnet_contract_used_bytes_total{direction}` as a cross-check against billable.
- **Two accounts at one gateway no longer overwrite each other** (<https://github.com/full-bars/sn/pull/30>): the stores were keyed by identity but several consumers still read a bare address, so a shared-gateway proxy silently merged the accounts. The earn tracker, the launch generation, the degraded-proxy reaper and the grade report now all use the identity. Credentialed proxies were previously invisible to the reaper, could report to the hub as ungraded, and could be left stuck in the cancel map after a failure.
- **A credentialed URL proxy is no longer counted twice** (<https://github.com/full-bars/sn/pull/30>): the match collector added it under its identity key and again under its bare address, so it appeared twice in `display` and inflated the `proxy remove --match` count.
- **A removed proxy's login is dropped** (<https://github.com/full-bars/sn/pull/30>): the client-JWT store migrated legacy keys but never pruned, so a removed proxy's login stayed on disk for the store's whole retention window and a re-add at the same address inherited a JWT minted for the old account. A rotation (same identity, new password) deliberately keeps its login.
- **A file source that cannot be read is reported as a failure** (<https://github.com/full-bars/sn/pull/31>): it left the resolution pending, so the status line read `starting: resolving proxies` and the snapshot later read it as a stuck startup. Running proxies are deliberately left alone.
- **A proxy source URL cannot leak its token into the logs** (<https://github.com/full-bars/sn/pull/31>): the per-source log lines and the operator warning use a redacted label that strips the query, the userinfo, and credential-bearing path segments, so a source like `.../token/SECRET/list` no longer reaches the important log or the warning, and one source no longer produces two different warning keys.
- **A no-source node stops claiming it is retrying** (<https://github.com/full-bars/sn/pull/31>): that configuration has nothing to retry, and the reason now matches the systemd status line.
- **The `top` menu now persists** (<https://github.com/full-bars/sn/pull/31>): the menu wrote through a settings path that nothing ever set and never loaded it back, so every choice was silently discarded and the theme reset on the next run. A theme forced by the environment (`NO_COLOR`, a dumb terminal) is not saved, so it does not outlive the terminal that forced it, and a config directory created by a first run under `sudo` is handed to the invoking user instead of staying root-owned and blocking their next save.
- **Live relay-egress connections count as client sessions** (<https://github.com/full-bars/sn/pull/57>): the session counter now reflects the connections that are actually carrying client traffic.
- **Proxy health follows the real transport connection** (<https://github.com/full-bars/sn/pull/58>): a proxy's health is driven by its real connection state, not by a stale signal.
- **The audit ring re-merges and persists after a hotswap drain** (<https://github.com/full-bars/sn/pull/43>): the successor re-merges the ring as a timestamp-ordered union after the parent drains, so the commands issued just before an update are neither lost nor duplicated.
- **`set baseline off` now stops the recorder** (<https://github.com/full-bars/sn/pull/44>): the command used to be sent in a form the recorder ignored. It now arrives as a value, so the recorder actually stops.
- **The pressure control no longer chases its own tail** (<https://github.com/full-bars/sn/pull/46>): the memory controller used to sawtooth against the GC governor. The control now stops reacting to its own effect.
- **The pressure, pool and reaper loops are supervised** (<https://github.com/full-bars/sn/pull/47>): a failed loop is restarted and a failure stays neutral, instead of taking the node down with it.
- **A slow proxy auth dial is no longer a failure** (<https://github.com/full-bars/sn/pull/32>): a slow auth dial was counted as a dead proxy. The provider now waits within a tolerance, and the transport choice reacts to measured cost.
- **The saved client login is looked up by proxy identity** (<https://github.com/full-bars/sn/pull/53>): the lookup used a bare address, so two accounts at one gateway could share the wrong login. It now uses the identity.
- **Parity fixes ported from the mature fork** (<https://github.com/full-bars/sn/pull/59>, <https://github.com/full-bars/sn/pull/45>): the small identity-key, audit and bandwidth differences are closed, the slow-retry semaphore survives a real give-up, and a source URL can no longer leak its token into a fetch error.
- **The OOM marker and retention log** (<https://github.com/full-bars/sn/pull/40>): the OOM start marker is written in every mode, and the retention log reopens after rotation. Linux-only tests stay out of the macOS and Windows test builds.

### Maintenance

It brings the `nativefee`, `chain`, `evmrpc` and `diagnostics` trees, an expanded `mainnet`, `sim-testnet`, `validator` and `miner` set, the qualification and mainnet release-build scripts, and a vendored `third_party/go-substrate-rpc-client`.
